# PR 22 bug audit and simplification

Reviewed automatic Windows hotspot startup, administrator approval, adapter/firewall selection, helper IPC, server ownership, package verification, pairing-page privacy and phone guidance under WP-303/WP-501.

| Finding | Fix | Evidence |
| --- | --- | --- |
| Shutdown released the signing/ownership lock before hotspot cleanup finished. A new server could acquire ownership while the previous helper was still turning the hotspot off. | Hold the lock until listeners and hotspot cleanup finish, and still release it if cleanup reports an error. | Deferred-cleanup and failed-cleanup regressions in `laptop-hotspot.test.mjs`. |
| The owning PowerShell helper called `Start-Process -Verb RunAs` directly. UAC can block that call before the helper reaches its pipe/cancellation polling. | Isolate elevation in a hidden, unelevated launcher process. The owner polls its parent pipe and terminates its own launcher on cancellation or timeout. Existing firewall scoping and approval requirements remain enforced. | Native synthetic approval success, denial, cancellation and EOF regressions; a live blocked-process experiment without elevation or firewall mutations completed cancellation in about 1.2 seconds. |
| Cancellation or helper loss during package verification waited for the entire inventory to be hashed. | Pass the session signal through startup verification and file streams; propagate cancellation instead of classifying the file as missing. | Package-verification cancellation regression and startup helper-loss regression. |
| Session shutdown after helper loss depended on the CLI's failure callback. Callers supplying their own callback could leave listeners and ownership active. | Let the session own its abort/cleanup lifecycle. Helper or listener errors abort the session and report the failure; the CLI only handles signals and safe error reporting. | Running-session abort and helper-loss regressions with a custom failure callback. |
| Hotspot monitoring checked address and interface index but ignored subnet or interface-name changes. | Stop sharing if the selected subnet or interface name changes, so the live session cannot retain an obsolete firewall scope. | Monitor review plus native adapter/subnet and firewall-scope regressions. |
| The parent's 30-second cleanup deadline was shorter than a pending 20-second WinRT call plus two bounded restoration calls. | Allow 75 seconds for those bounded operations before terminating a stuck helper and reporting manual cleanup guidance. | Bounded WinRT-call and supervisor timeout review; live normal startup/shutdown remains successful. |

Simplification removes the option loop and duplicate-option set now that the CLI accepts only one optional `--port` pair. Session ownership replaces the CLI's extra session variable and abort/finish callback. Cleanup uses one error-collecting path so listener or discovery failures do not prevent hotspot and lock release. Default session failure reporting also uses the existing safe error formatter.

The launcher uses the documented [Windows elevation and argument quoting behavior of Start-Process](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.management/start-process?view=powershell-5.1). Its arguments contain executable/script paths and a port; no hotspot password or pairing code is passed. It can leave a previously accepted, short-lived elevated firewall operation to finish, but that operation only manages the existing narrowly scoped rule and cannot change hotspot ownership.

Validation: `pnpm test:laptop`, `pnpm quality`, `pnpm test:privacy`, the existing project Python test environment, `pnpm build:web` and `scripts/Test-Wp001.ps1`. Exact command results and candidate CI checks are recorded in PR #22. Live laptop verification covers hotspot startup, authenticated catalog access, laptop-only pairing instructions, absence of an upstream listener and normal shutdown. Real network details, credentials and diagnostic logs remain local and ignored; committed test fixtures are explicitly synthetic.

Traceability: WP-303, WP-501; REQ-CAT-002, REQ-USR-002, REQ-SEC-001, REQ-UX-001, REQ-A11Y-001; T-INT-002, T-SEC-002, T-E2E-001; ADR-052. No protocol/schema, dependency, package payload or trust-policy changes are introduced by this audit.

Physical iPhone joining, app QR pairing, state installation, interruption/reconnection, low storage and offline map use remain separate acceptance checks deferred by the owner. The new UAC launcher is covered by synthetic approval control and blocked-process cancellation checks; a fresh secure-desktop approval with a phone transfer still needs physical acceptance. Automated evidence does not establish those results.
