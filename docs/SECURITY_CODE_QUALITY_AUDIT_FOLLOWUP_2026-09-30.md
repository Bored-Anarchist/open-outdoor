# Repository audit follow-up — 2026-09-30

Baseline: `5339b8b72981d09f6841897fbd6248fe838a604c`, the existing `codex/security-quality-audit` branch. The [initial audit](SECURITY_CODE_QUALITY_AUDIT_2026-09-30.md) retains the earlier twenty fixes and dependency remediation. This follow-up identifies and implements eight additional improvements; it does not replace that historical evidence.

## Scope and evidence

The review inventoried all 688 tracked files and surveyed application/package sources, Python and JavaScript data tools, native Swift integrations, PowerShell scripts, workflows, dependency locks, configuration, and governance documentation. Manual review concentrated on imports/exports, tracking recovery, private persistence, catalog signatures and activation, network acquisition, laptop transfers, and CI. Generated geographic assets were inspected through their contracts and existing integrity tests rather than manually reviewing each feature. Ignored private datasets and account credentials are outside this audit.

The unchanged baseline passed the complete quality suite: 480 Vitest tests, 153 Node release-tool tests, and three dependency compatibility tests. New adversarial tests were then run against baseline source, with fixed files saved and restored byte-for-byte in a `finally` block: 32 JavaScript test cases failed across five files, and Python reported 19 failing assertions/subtests. With the fixes restored, the full suite passed with 530 Vitest tests, the same 153 release-tool tests, three compatibility tests, and 14 Python tests. CI gate tests execute the actual workflow Bash script across success, failure, cancellation, skipping, and missing-output cases.

## Findings and implemented improvements

| Finding | Priority and affected behavior | Improvement and reasoning | Regression evidence |
| --- | --- | --- | --- |
| FUP-001 | P1: a recording batch can partly commit before a later duplicate sequence conflicts | Stage and validate the complete batch before updating committed observations or the checkpoint. Reject invalid sequence numbers. This leaves failures safe to retry and avoids an observation/checkpoint disagreement. | Existing-sequence conflict, within-batch conflict, invalid sequence after an otherwise valid point, and successful retry |
| FUP-002 | P2: recording state and observation objects escape by reference | Return copies of lifecycle states and clone observations when entering/leaving the state machine. TypeScript `readonly` does not protect objects at runtime; a caller could otherwise rewrite immutable observations or change the final sequence. Track the highest sequence while inspecting the incoming batch instead of sorting the full activity on every commit. | Mutation of the original point, returned coordinates, transition result, and state snapshot cannot alter the recording |
| FUP-003 | P1: privacy trimming measures geodesic distance but interpolates longitude/latitude linearly | Interpolate on the corresponding great-circle arc. The old interpolation sends a date-line crossing toward Greenwich and gives incorrect trim distances at high latitudes. Reject nearly antipodal segments, whose short arc is ambiguous, rather than reporting successful trimming. This affects the shared route export API; it is not evidence of an automatic upload. | Both date-line directions, a high-latitude route, distance retained after trimming both endpoints, and antipodal rejection |
| FUP-004 | P2: the public GPX/GeoJSON route parsers accept invalid resource limits | Validate positive safe integer byte and point limits before parsing. `NaN`/`Infinity` otherwise defeat comparisons and silently disable the intended bounds. Centralize validation for these public entry points; selected-file imports already validate their own limits. | Both parsers reject zero, negative, fractional, infinite, and NaN limits |
| FUP-005 | P1: archive validation is inconsistent across Windows aliases and malformed budgets | Reject Windows device names, alternate data streams, control/forbidden filename characters, trailing dots/spaces, case/separator collisions, and file/child conflicts regardless of member order. Reject invalid budgets and unknown/special member types before extraction. Apply corresponding checks to TypeScript archive metadata and Python ZIP inspection. These are laptop-side ingestion boundaries, not a demonstrated mobile remote exploit. | Unsafe names, case/separator duplicates, parent-file conflict in both orders, NaN/infinite budgets, explicit safe directories, and special ZIP members |
| FUP-006 | P2: malformed decrypted backup structures raise incidental JavaScript errors | Validate payload, manifest, counts object, attachment list cardinality, identifiers, ownership, media fields, and attachment hash types before dereferencing them. Return a typed `BackupError` so authenticated malformed data cannot bypass the expected failure/recovery path. AES-GCM verification remains mandatory; possession of authenticated input is not proof of a valid application schema. | Null/missing structures, mismatched manifest list, malformed attachments, empty identifiers, orphan ownership, and a valid attachment restore |
| FUP-007 | P1: bounds/distance filtering can exceed the engine's function-argument limit on large geometry | Replace `Math.min/max(...points)` and equivalent multi-geometry distance spreads with bounded-argument loops/reductions. Bounds need one pass and no four intermediate coordinate arrays. Complexity remains linear; the change removes an avoidable scale-dependent crash without claiming a measured frame-rate improvement. | A synthetic 200,000-position trail can be filtered both inside and outside bounds |
| FUP-008 | P2: `windows-quality` reports routing success before the Windows tests finish | Move the stable status name to an aggregate job that always waits for routing and Windows checks. Require successful tests whenever routed; allow an explicit documentation-only skip. Failure/cancellation/missing route output must fail the gate. The tracked ruleset currently requires documentation integrity only, so this corrects reporting and future gate enforcement rather than claiming an active protected-branch bypass. | Twelve executions of the actual Bash gate plus a contract test for dependencies, `always()`, environment bindings, and the unique stable name |

## Quality, readability, and maintainability assessment

Strict TypeScript settings, explicit module boundaries, versioned algorithms, immutable durable sample intent, pinned dependencies/actions, signature checks, read-only catalog capabilities, private-data classification, and the existing failure-injection tests provide a strong baseline. The fixes reinforce those contracts with centralized route-limit validation, explicit backup error handling, archive preflight rules, atomic batch acceptance, and meaningful workflow results. They preserve the existing public APIs and private database schema.

Large source files such as the map screen and private-source normalization remain a maintenance concern. A broad decomposition would touch unrelated behavior without evidence of a specific defect, so this corrective change confines refactoring to the failing boundaries. Future feature work should extract cohesive pure transformations while retaining the existing integration tests. This is an architectural observation, not a claim that a full screen rewrite was implemented.

## Validation and practical limits

- `pnpm quality`: workspace storage policy, type builds, formatting, release/workflow/native contract checks, 530 Vitest cases, 153 release-tool cases, and three dependency compatibility cases passed.
- `PYTHONPATH=python .venv/Scripts/python.exe -m unittest discover -s python/tests`: 14 tests passed on the existing pinned environment.
- `pnpm build:web`: production browser bundle passed.
- `pnpm build:ios:bundle`: public iOS JavaScript/Hermes export passed (698 modules); this is bundle verification, not native compilation or device acceptance.
- Privacy suite: 12 tests passed. A public-only snapshot of all 690 tracked/proposed files passed the boundary scanner; 645 bounded text files contained no recognized private-key, AWS, GitHub, or OpenAI credential patterns. Binary content, large text files, unknown credential formats, and ignored private material remain outside that pattern-scan claim. `git diff --check` and the WP-001 governance/relative-link check passed.
- `NODE_USE_SYSTEM_CA=1 pnpm audit --json`: exit zero, no advisories in any severity category, 591 unique package/version pairs. The first plain request failed to fetch; the successful query used the trusted Windows certificate store and retained TLS verification. The owner explicitly approved advisory metadata transfer. [Node certificate-store documentation](https://github.com/nodejs/node/blob/main/doc/api/cli.md) explains that option; [npm audit documentation](https://docs.npmjs.com/cli/audit.html/) describes advisory metadata transfer. This is a point-in-time npm result, not coverage of unknown vulnerabilities or native/Python ecosystems.
- The repository-wide review cannot establish UIKit/CoreLocation device behavior, native compilation, battery usage, or production release acceptance on Windows. Existing native source-contract checks passed. Mac/iPhone acceptance still belongs to the documented release gates.
- Archive checks preflight names, declared sizes, and member types. They do not replace isolation against concurrent privileged filesystem mutation or dishonest archive metadata during actual decompression.
- This follow-up did not repeat the initial audit's full history scan. Current public files and the final diff receive the repository privacy/public-boundary and whitespace checks; the original audit records the history-scan scope and exclusions.
