# WP-010 evidence — catalog trust and production-signing foundation

**Status:** Implementation complete; protected CI passed; review and merge pending
**Requirements:** REQ-CAT-006, REQ-CFG-001; foundation contribution to REQ-REL-001
**Risk/threat/decision:** R-023, THR-005, ADR-031
**Verification:** T-REL-003-C01 through C08

Implemented a platform-neutral catalog trust boundary in `@open-outdoor/config`. The version-1 Ed25519 envelope binds channel, trust root, key ID, manifest SHA-256, monotonic anti-replay version, and signing time. Trust policy is supplied independently from catalog bytes. Missing, malformed, altered, wrong-channel, wrong-root, replayed, untrusted, revoked-key, invalid-signature, and crypto-provider-failure candidates fail closed.

The committed channel configuration pins `public-v1`, `local-development`, and `private-external` trust roots. It contains no signing keys or private trust material. Public/private production channels reject unsigned catalogs. The local channel accepts them only with the exact visible label `UNSIGNED DEVELOPMENT CATALOG — NOT FOR PRODUCTION`.

- `pnpm release:verify`: release configuration, catalog trust configuration, signature schema, and six workflow files passed.
- `pnpm test:catalog-trust`: eight T-REL-003 cases passed, including the committed replay and wrong-channel synthetic fixtures.
- `pnpm quality:types`: all configured TypeScript projects passed.

The tests generate ephemeral Ed25519 keys in memory; fixture keys are not committed. Actual production key generation, custody, provisioning, rotation, and revocation follow `docs/CATALOG_SIGNING_KEY_PROCEDURE.md` and remain external release-owner operations. The verifier authorizes candidates but does not switch the active catalog pointer; interruption-safe activation and last-known-good rollback remain WP-303.
