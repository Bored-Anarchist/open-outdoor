# WP-306 evidence

**Status:** Complete encrypted backup/restore implementation and local acceptance passed on 2026-09-02

The version 2 authenticated AES-256-GCM container now encrypts a complete manifest for every private SQLite collection, a whole-snapshot SHA-256 digest, catalog version inventory, and selected attachment identity, ownership, media type, size, and hash. Reference catalogs remain identifiers rather than copied catalog bytes. Restore accepts the current and previous container format and private schema, migrates only after authentication and integrity validation, calculates staging/free-space needs, and exposes an atomic stage/commit/rollback target.

The pre-uninstall guard blocks continuation when there is no verified backup, private data changed after verification, or the user has not confirmed an independently held recovery secret. Wrong key, tampering, truncation, corrupt attachments, low space, previous-version migration, and swap rollback all fail before replacing existing private data.

Verification: strict TypeScript build and the expanded `packages/backup/test/backup.test.ts` acceptance suite.
