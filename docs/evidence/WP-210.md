# WP-210 evidence

**Status:** Connector foundation and ADR-046 RIDB bulk-download migration implemented on 2026-08-31; live reviewer acceptance pending

## Superseding RIDB acquisition decision

ADR-046 replaces live RIDB API acquisition with the official [daily RIDB JSON download](https://ridb.recreation.gov/download). The connector reads the ZIP central directory with a bounded suffix request, range-fetches only the facilities and facility-address entries, enforces entry/expansion/payload limits, joins on `FacilityID`, selects `AddressStateCode=NY`, and stores the resulting raw acquisition artifact with its byte count and SHA-256. The guided runner validates the current ZIP end record and required entries with a 64 KiB suffix request and records archive metadata plus a directory-sample SHA-256. Neither the tester nor the mobile application supplies or stores a RIDB API key.

The historical implementation evidence below describes the connector foundation as originally completed. Its RIDB API endpoint, paging, secret declaration, guided probe, and associated tests are superseded. `T-INT-003-C06` and `C07` now require the credential-free ZIP registry plus deterministic range extraction and New York filtering. NPS header-secret handling, OSM checksum pinning, 3DEP metadata retention, rights gates, and coverage reporting remain applicable.

## Original implementation evidence

The production registry targets the official RIDB facilities API, NPS parks/campgrounds/alerts API, a dated checksum-pinned Geofabrik New York OpenStreetMap PBF, and USGS National Map 3DEP product discovery. These are real open/public-data source definitions; synthetic records exist only as public test fixtures and are never substituted into a production bundle.

RIDB and NPS credentials are injected under declared external secret names and sent only in headers. Deterministic API paging preserves source partitions. OSM rejects `latest` or unchecksummed extract locators, verifies the pinned MD5 or SHA-256 before decoding, and retains OpenStreetMap/Geofabrik attribution plus ODbL identity. 3DEP accepts only allowlisted HTTPS product URLs and preserves bounds, byte size, resolution, publication time, and vertical datum.

Every source independently passes the connector manifest and acquisition/retention/derivation/offline/public-distribution rights gates. Coverage reports count records, elevation products, geometry, source freshness, stale sources, and missing RIDB/NPS/OSM/3DEP families.

`T-INT-003-C06` through `C09` cover registry/rights review, paging and secret transport, NPS/3DEP normalization, and OSM checksum pinning. `T-REL-002-C03` covers family/freshness/geometry/elevation coverage.

Verification after the RIDB migration: strict TypeScript build plus the WP-210, guided-acceptance, and gate Vitest suites. Live archive-directory availability is checked by the guided runner; source-specific accuracy sampling and production basemap compilation remain later work-package gates.
