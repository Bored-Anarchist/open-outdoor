# WP-008 evidence — private/reference database, protection, and compatibility spike

**Status:** Implementation complete; physical iPhone acceptance pending

Accepted ADR-017, ADR-018, and ADR-041 for the Phase 0 spike. The autolinked Swift storage coordinator uses native SQLite3, opens the private user database with read/write/create plus WAL, and opens catalog databases with `SQLITE_OPEN_READONLY`. Catalog paths resolve symlinks and must remain below the declared public/private catalog roots. The active spool, sealed user database, WAL/SHM, and catalogs receive their declared iOS protection and backup-exclusion attributes.

The platform-neutral storage contract provides:

- explicit query/write capabilities with no writable catalog or writable-attach capability;
- current-plus-previous app/catalog compatibility preflight before mutation;
- the exact combined-catalog free-space formula, including the 9 GiB maximum-profile result;
- checksum, compatibility, free-space, and remap fail-closed behavior; and
- an interruption matrix that retains the old catalog before pointer switch, rolls back after an unconfirmed switch, and never changes private record digests.

Windows-verifiable cases pass for T-INT-001-C01–C02, T-INT-002-C01–C10, T-INT-006-C01–C04/C06, and the read-only iTunes `Manifest.db` inspector tests. T-INT-006-C05 is reserved for WP-107 backup compatibility.

The Phase-0-only native harness seeds synthetic user tables/WAL/SHM, attachments, diagnostics, public/private catalogs, deterministic version A/B remaps, an unresolved association, and every activation checkpoint. It reports record counts/hashes plus effective protection/backup attributes and shares only one generated JSON file. Physical system-backup attempt on 2026-08-23: the operator completed a Windows local backup with encryption enabled. Private inspection confirmed `IsEncrypted: true` and a non-SQLite encrypted `Manifest.db`. The Phase 0 read-only inventory inspector cannot parse that container without the backup decryption work explicitly deferred by ADR-041, so no backup-exclusion acceptance is claimed from this attempt. The procedure now requires a temporary unencrypted local inventory backup, followed by deletion after the redacted report is retained. Physical retest remains pending.

Environment follow-up: although current Apple documentation describes an optional **Encrypt local backup** checkbox, the operator reported that the installed Windows backup UI exposes only encrypted local backups and no control to disable encryption. The encrypted backup is retained and no password, device identifier, payload, or private backup path is recorded. System-backup inventory therefore remains unverified on this pinned environment; resolving it requires an Apple-supported plaintext inventory path or a separately approved encrypted-container scope, not third-party decryption during WP-008.
