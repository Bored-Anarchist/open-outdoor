# WP-007 evidence — minimal native tracker and durability spike

**Status:** Implementation complete; physical iPhone acceptance pending

Implemented an autolinked Expo iOS module containing a Swift `CLLocationManager`/`CMAltimeter` tracker spike. During an explicit active session it writes newline-delimited, monotonically sequenced observations to `Library/Application Support/Tracking/Active`, synchronizes every observation, applies `completeUntilFirstUserAuthentication`, and excludes the directory, manifest, and spool from system backup. A durable `active-session.json` identifies session/mode/spool without adding per-sample manifest writes. Relaunch inspection derives the highest contiguous sequence from synchronized JSONL, ignores only an undecodable torn final line, and exposes inspect, recover, and discard controls through main-queue Expo module functions.

The shared replay contract accepts out-of-order batches deterministically, ignores identical duplicates, rejects conflicting duplicates, and reports sequence gaps rather than inventing samples. The native implementation remains energy-conscious by running sensors only for active recording, requiring explicit High Accuracy, applying lower-frequency Balanced/Endurance filters, and avoiding continuous polling. No battery-life result is claimed.

Windows-verifiable evidence:

- T-PHY-001-C01 through C06 contract prechecks pass for contiguous/out-of-order replay, duplicate idempotence, conflict rejection, gap reporting, and invalid state.
- `tools/validate-native-spikes.mjs` confirms native autolinking, main-queue recovery/readback controls, durable manifest/spool policy, torn-line handling, barometer/location sources, and the energy-conscious implementation constraints.
- Release configuration binds profile `iphone14-ios26.2-phase0-v1`, 30-second/one-batch durability, 500 ms acknowledgement, 150 MiB memory, and the deferred energy policy.
