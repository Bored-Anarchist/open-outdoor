# WP-007 evidence — minimal native tracker and energy baseline

**Status:** Implementation complete; physical iPhone acceptance pending

Implemented an autolinked Expo iOS module containing a Swift `CLLocationManager`/`CMAltimeter` tracker spike. During an explicit active session it writes newline-delimited, monotonically sequenced observations to `Library/Application Support/Tracking/Active`, synchronizes every observation, applies `completeUntilFirstUserAuthentication`, and excludes the directory and spool from system backup. Background location declarations and purpose strings are committed in the iOS app configuration. The feasibility UI exposes permission request, mode selection, start, and stop controls through main-queue Expo module functions so the physical protocol can exercise this spike without claiming the WP-103 production bridge.

The shared replay contract accepts out-of-order batches deterministically, ignores identical duplicates, rejects conflicting duplicates, and reports sequence gaps rather than inventing samples. Its energy evaluator requires the configured number and duration of runs and fails thermal warnings, continuous retries, unintended background sessions, missed stop, memory overruns, and battery overruns.

Windows-verifiable evidence:

- T-PHY-001-C01 through C06 contract prechecks pass for contiguous/out-of-order replay, duplicate idempotence, conflict rejection, gap reporting, and invalid state.
- T-PHY-002-C01 through C04 evaluator prechecks pass for repetition, duration, thermal/runtime blockers, High Accuracy budget absence, and warm-up exclusion.
- `tools/validate-native-spikes.mjs` confirms native autolinking, main-queue callable controls, background declarations, protected spool policy, durable synchronization, and barometer/location sources.
- Release configuration binds profile `iphone14-ios26.2-phase0-v1`, 30-second/one-batch durability, 500 ms acknowledgement, 150 MiB memory, three four-hour runs, and Balanced/Endurance energy limits.

Still required on the iPhone 14 running iOS 26.2:

- native module compilation in the pinned macOS workflow and signed installation;
- start/stop acknowledgement timing;
- screen-lock, suspension, poor-GPS, process-death, relaunch, and missed-stop behavior;
- active-spool protection inspection after first unlock and safe pre-first-unlock behavior;
- three valid four-hour screen-off runs each for Balanced and Endurance after a warm-up;
- a measured, approved High Accuracy energy limit; and
- p95 screen-off resident memory.

No browser, Windows replay, or synthetic battery result is claimed as physical acceptance.
